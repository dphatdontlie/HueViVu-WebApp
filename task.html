2. EXECUTIVE SUMMARY (TÓM TẮT DÀNH CHO LÃNH ĐẠO)

2.1. Dự án giải quyết vấn đề gì?

HueViVu là ứng dụng web định vị là Người bạn đồng hành du lịch AI cho Cố đô Huế. Dự án giúp du khách tự túc xây dựng lịch trình khả thi theo thời gian, ngân sách, phương tiện, thích ứng động với biến cố thời tiết hoặc thay đổi lịch trình, tra cứu offline khi mất kết nối mạng, kết hợp trải nghiệm tương tác 3D và định hướng.

2.2. Điểm số đánh giá & Mức độ tin cậy

  • Điểm tổng hợp: 56.7 / 100 (Xếp loại: Trung bình khá / Beta cục bộ).
  • Mức độ tin cậy: Cao đối với kiến trúc, mã nguồn, bảo mật; Trung bình đối với đo lường hiệu năng runtime thực tế do thiếu node_modules.

2.3. Điểm mạnh và Rủi ro cốt lõi

  • Điểm mạnh: Thuật toán tìm đường A* bám sát tập quán du lịch Huế; cơ chế thích ứng động qua preview trước khi confirm; bảo vệ trạng thái với khóa lạc quan (optimistic locking); khả năng phục hồi offline ấn tượng qua Service Worker và LocalStorage snapshot.
  • Rủi ro cốt lõi (Blockers): P0 Lỗi khởi tạo database sạch do thiếu fixture địa điểm khiến endpoint health check trả về HTTP 503 và chặn luồng tạo chuyến đi; P1 Thiếu rate limiting tại các API xác thực và phản hồi; P1 Rò rỉ thông tin lỗi nội bộ qua response 500; P1 Module AI RAG và YOLO vision còn là stub rỗng.

3. TỔNG QUAN DỰ ÁN (PROJECT OVERVIEW)

Hệ thống được tổ chức thành các phân hệ: Khách vãng lai (Guest session ẩn danh), Người dùng đăng ký, Collector (thu thập dữ liệu), Reviewer (thẩm định nội dung), và Admin (quản trị toàn hệ thống). Các module chính bao gồm Trip Planner & Optimization, Adaptive Engine, Discovery & Map, Weather Engine, Live Guide & AI Chat, 3D Heritage Experience và Admin Quality Assurance.

4. ĐÁNH GIÁ KIẾN TRÚC HỆ THỐNG

HueViVu áp dụng mô hình Modular Monolith trên nền tảng Next.js 15.5.27 (App Router) kết hợp SQLite (better-sqlite3). Ranh giới giữa các engine thuần túy (như astar.ts, itinerary-validator.ts, trip-adapter.ts) và tầng API route được tách bạch rất tốt, giúp dễ dàng kiểm thử đơn vị.

Ngăn xếp công nghệ hiện đại bao gồm Next.js 15, React 19, TypeScript, SQLite (better-sqlite3), Tailwind CSS, Leaflet, Three.js (React Three Fiber), Google Generative AI SDK, và BullMQ. Sự kết hợp này mang lại hiệu năng cao trên client nhưng đòi hỏi lưu ý về giới hạn single-writer của SQLite.

7. ĐÁNH GIÁ CHẤT LƯỢNG MÃ NGUỒN

  • [CQ-01] [P2] Thuật toán Priority Queue trong A* (src/lib/astar.ts:37) thực hiện gọi phương thức sort() trên toàn bộ mảng sau mỗi lần chèn, làm tăng độ phức tạp tính toán CPU lên $O(N \log N)$ khi số lượng trạng thái lớn. Khuyến nghị thay thế bằng Binary Min-Heap chuẩn.
  • [CQ-02] [P2] Thiếu kiểm tra cấu trúc schema khi cập nhật thủ công lịch trình tại /api/trips/[id]/save-itinerary.
  • [CQ-03] [P3] Tồn tại các tệp rác, file backup (*.bak, script tạm ở thư mục gốc) làm ô nhiễm git repository.

8. ĐÁNH GIÁ CƠ SỞ DỮ LIỆU

  • [DB-01] [P0] Lỗi khởi tạo sạch cơ sở dữ liệu: Hàm seedData trong src/lib/db.ts hiện đã xóa bỏ dữ liệu mẫu cũ nhưng không nạp dữ liệu địa điểm mặc định. Khi chạy trên môi trường mới không có sẵn file huevivu.db, bảng places trống hoàn toàn, gây lỗi 503 cho /api/health và làm tê liệt luồng tạo chuyến đi.
  • [DB-02] [P2] Vấn đề N+1 Query tại bảng tin cộng đồng (/api/feed): Vòng lặp duyệt qua danh sách chuyến đi thực hiện thêm 2 câu truy vấn SQL riêng lẻ để kiểm tra trạng thái like và save của user.

9. ĐÁNH GIÁ API VÀ TÍCH HỢP

Hệ thống REST API được thiết kế rõ ràng với hơn 25 endpoint. Các dịch vụ bên ngoài bao gồm Open-Meteo (thời tiết), Valhalla / Google Routes (định tuyến), Google Gemini API (AI chat & vision), và Google Translate TTS (scrape không chính thức).

10. ĐÁNH GIÁ BẢO MẬT

  • [SEC-01] [P1] Thiếu Rate Limiting tại các API đăng nhập, đăng ký và phản hồi, mở ra rủi ro brute-force và spam dữ liệu.
  • [SEC-02] [P1] Rò rỉ thông tin lỗi nội bộ chi tiết (err.message) qua response HTTP 500 tại nhiều API route.
  • [SEC-03] [P1] Endpoint TTS sử dụng kỹ thuật scraping không chính thức của Google Translate, rủi ro bị chặn IP cao.
  • Điểm bảo mật tốt: Sử dụng bcryptjs (salt rounds 10), loại bỏ password hash khỏi response, phân quyền RBAC chặt chẽ và cấu hình Security Headers đầy đủ qua middleware.
